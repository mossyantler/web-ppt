# onething 스킬 정교화

- 작성 시작: 2026-08-01
- 상태: 구현 완료 (결정 12개 → SKILL.md 반영 완료 2026-08-02)

## 한 줄 요약
onething 스킬 자체를 사용자 대화 스타일에 더 맞게 다듬는다.

## 합의된 결정

### 1. 설명의 눈높이 — 용어 처리
- **정한 것**: 명세서 맨 아래에 "이번에 나온 말" 용어집을 쌓는다. 본문에서는 처음 등장할 때만 풀이한다. 이후 사용자가 "그거 뭐였지?"라고 요청하면 그때 한 번 더 설명한다. 요청 없이 매번 힌트를 붙이지는 않는다.
- **왜**: 매번 반복은 지겹고, 용어집이 있으면 잊었을 때 찾아볼 수 있다. 설명은 필요할 때 당겨 쓰는 방식.
- **정한 사람**: 사용자

### 2. 코드 구조를 얼마나 보여줄지
- **정한 것**: 지도 + 매 질문 위치 표시 방식. (1) 질문 시작 전에 관련 구조를 5줄 이내 "지도"로 한 번 보여주고, 모르는 부분을 먼저 물어볼 기회를 준다. (2) 이후 모든 질문 머리에 "📍 지도 ②번 자리" 식으로 현재 위치를 한 줄 표시한다.
- **왜**: 원래 목표가 "내 서비스에 뭐가 들어있는지 알기"이므로, 매 결정이 전체 그림의 어디를 건드리는지 항상 보여야 한다.
- **정한 사람**: 사용자

### 3. 한 세션에 질문 몇 개까지
- **정한 것**: 7개마다 멈춰서 "여기까지 정리하고 멈출까요, 더 갈까요?"를 묻고 사용자가 고른다. 사용자가 계속 가자고 하면 다음 7개를 진행한다. 내가 임의로 계속 진행하지 않는다.
- **왜**: 무제한이면 결국 지쳐서 위임하게 되고, 3개는 흐름이 너무 자주 끊긴다.
- **정한 사람**: 사용자

### 4. 위임이 반복될 때의 제동
- **정한 것**: "너가 정해"가 연속 3번 나오면 한 번 멈춘다. 내가 정한 최근 3개를 한 줄씩 요약해 보여주고, 질문이 어려웠는지 한 번만 확인한다. 확인 후에는 다시 진행한다(추궁하지 않는다).
- **왜**: 위임 자체는 괜찮지만 쌓이는 걸 사용자가 못 느끼면 다시 "코드의 외주화"가 된다.
- **정한 사람**: 사용자

### 5. 이해 확인 장치
- **정한 것**: 매 질문마다 되묻지 않는다. 7개마다 쉬어갈 때 "이 중 다시 설명했으면 하는 게 있나요?"를 한 번 묻는다. 사용자가 항목을 고르면 그 결정 하나를 다시 설명한다.
- **왜**: 매번 되묻는 건 시험 보는 느낌이라 부담. 쉬는 지점에서 한 번이면 충분.
- **정한 사람**: 사용자

### 6. 앞 결정 되돌리기
- **정한 것**: 사용자가 앞 결정을 바꾸겠다고 하면, 즉시 바꾸고 그 결정 때문에 전제가 틀어진 질문들을 찾아 **차례로 다시 묻는다**(한 번에 하나씩 규칙 그대로). 명세서에는 바뀐 이력도 남긴다.
- **왜**: 비개발자는 뒤 질문에 가서야 앞 질문의 의미를 이해하는 경우가 많다. 조용히 바꾸면 앞뒤가 안 맞는 명세서가 된다.
- **정한 사람**: 사용자

### 7. 명세서를 두 벌로 나눈다
- **정한 것**: 명세서를 파일 두 개로 나눈다. (갱신 주기는 12번에서 다시 정했다)
  1. **사람용** `docs/specs/<주제>.md` — 한국어, 쉬운 말, **요약하지 않고 결정 전문을 그대로** 남긴다. 용어집 포함.
  2. **AI용** `docs/specs/<주제>.ai.md` — 영어, 압축된 기계 친화 형식. 다음 세션에서 AI가 컨텍스트를 빠르게 되찾는 용도.
- **왜**: 사람이 읽을 문서와 AI가 읽을 문서는 최적 형태가 다르다. 한 파일에 둘 다 맞추면 양쪽 다 나빠진다. 사람용을 요약하면 나중에 혼자 읽을 때 근거가 사라진다.
- **정한 사람**: 사용자

### 8. 구현 단계는 이 스킬 밖
- **정한 것**: onething은 기획·합의까지만 담당한다. 합의가 끝나면 명세서 경로를 알리고 "구현 시작할까요?"로 종료한다. 구현을 어떤 속도로 할지는 이 스킬이 정하지 않는다.
- **왜**: 스킬의 범위를 하나로 유지. 구현 속도는 나중에 따로 정한다.
- **정한 사람**: 사용자

### 9. 기존 코드 학습은 별도 스킬로
- **정한 것**: "이미 만들어진 기능을 한 조각씩 배우는" 모드는 onething에 넣지 않고 별도 스킬로 분리한다. onething은 "새로 정하기"(내가 묻고 사용자가 답함) 전용이다. 학습 스킬은 역할이 뒤집힌다 — 내가 한 조각씩 설명하고 사용자가 질문한다.
- **왜**: 두 모드는 대화 방향이 반대라 한 스킬에 넣으면 규칙이 섞인다.
- **정한 사람**: 사용자

### 10. 발동 방식 — 제안형
- **정한 것**: 자동으로 켜지 않는다. 결정할 게 많아 보이는 요청(새 기능, 구조 변경, 여러 파일에 걸친 작업)이 들어오면 "이건 onething으로 하나씩 갈까요?"를 **한 번 묻고 답을 기다린다**. `/onething`으로 직접 부르면 묻지 않고 바로 시작한다.
- **왜**: 자동 발동은 간단한 일까지 느려지고, 명시 호출만으로는 켜야 할 때를 놓친다.
- **정한 사람**: 사용자

### 11. 다른 스킬과의 우선순위 (재질문 후 확정)
- **정한 것**: onething이 진행 중이면 autopilot·ultrawork·ralph·team 등 자동 실행 스킬을 **내 판단으로는 절대 발동하지 않는다**. 키워드가 감지돼도 무시한다. 단, 사용자가 "이젠 autopilot으로 가"처럼 **명시적으로 전환을 요청하면** onething을 종료하고(명세서에 진행 상황 저장) 그 스킬로 넘어간다.
- **왜**: 자동 실행 스킬은 "몰아서 빨리"가 목적이라 onething의 "하나씩 천천히"와 정면 충돌한다. 다만 전환 권한 자체는 사용자에게 있어야 한다.
- **정한 사람**: 사용자
- **이력**: 처음엔 "완전 차단"으로 정했다가, 재질문 후 "사용자가 말하면 전환 가능"으로 수정.

### 12. 명세서 갱신 주기 (토큰 절약)
- **정한 것**:
  - **사람용**은 7개 쉬어가기 지점, 사용자가 중단할 때, 다른 스킬로 전환할 때 쓴다. 결정 하나마다 쓰지 않는다.
  - **AI용**은 모든 질문이 끝난 뒤 **딱 한 번** 쓴다. 대화 기억이 아니라 **완성된 사람용 파일을 읽어서** 영어로 압축한다. 사람용이 원본, AI용은 파생물이다.
  - 예외: 대화가 아주 길어져 앞부분이 요약될 조짐이 보이면 7개를 안 기다리고 사람용을 즉시 저장한다.
  - 중단 후 재개할 때는 사람용만 읽는다. AI용은 아직 없을 수 있다.
- **왜**: 매번 두 파일을 고치면 12개 결정에 편집 24회. 이 방식이면 3회다. 사람용을 매 결정마다 써야 할 실질적 이유가 없었고("바로 남아야 안심된다"는 근거 없는 가정이었다), 유일한 위험인 "세션이 끊기면 최대 6개 손실"은 대화 기록으로 복구된다. AI용을 완성본에서 뽑으면 중간 상태를 여러 번 쓸 필요도 사라지고, 두 파일이 어긋날 일도 없다.
- **정한 사람**: 사용자
- **이력**: (1) 처음엔 두 파일 다 매 결정마다 갱신. (2) 토큰 지적 후 AI용만 7개마다로 변경. (3) "사람용은 왜 매번?" 재검토 후 사람용도 7개마다로 통일하고, AI용은 사람용 완성 후 1회 생성으로 확정.
