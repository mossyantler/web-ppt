# SPEC (AI context): M3 editor UI

status: agreed | source: `m3-편집기-화면.md` (human original, Korean)
goal: A browser screen for editing weekly-report slides by clicking.
user profile: non-developer. Root problem = "outsourcing of code". Ask one question per reply.

## ARCHITECTURE CONSTRAINT (do not violate)

The screen renders only. All mutation goes through server commands, never through
live DOM serialization. This is what preserves P2 ("bytes outside the edited range
are identical"). Plan decision Z2.

Four parts: (1) slide rail, (2) slide canvas, (3) select/manipulate, (4) save.

## DECISIONS

D1 scope
- Ship: text editing, reordering, add/remove elements, save, undo.
- Do NOT ship: adding/removing whole slides, free positioning (M6), diagnostics (M4).

D2 selection — mirror PowerPoint
- Single click selects (outline + floating toolbar). Second click enters text editing.
- Esc returns to selection. Click outside deselects. No "edit" toggle button.
- HISTORY: first agreed as "edit button puts the whole slide in edit mode"; reverted
  because every click then lands a caret, leaving no way to select a card to move or
  delete. Do not reintroduce a whole-slide edit mode.

D3 reordering
- Both drag and up/down buttons. Both issue the same command.
- Drag inserts into a slot, not at a point — show an insertion line. Slides use flow
  layout (head/body/foot, stacked), not x/y coordinates.

D4 save
- Autosave on leaving an edit. No save button.

D5 undo
- Ctrl+Z plus visible undo/redo buttons in the top bar.

D6 slide rail
- Click to navigate, plus drag to reorder slides.
- REQUIRES new server work: `moveSection` does not exist yet, and `renumberPages`
  follows from it.

D7 adding elements
- `+` under the selected element opens a short list; user picks the type.
- Not "same type automatically" — that offers no way to insert a different type.

D8 opaque leaves (equation, progress)
- equation: double click turns the spot into a text field; rendered result previews
  live underneath.
- progress: drag the bar end, and edit the adjacent number for an exact value.
- Editing cost must not exceed that of an authored leaf — grammar.md §3.2 L2 clause 6
  makes this an M3 acceptance criterion. W31 has 53 equations; this is a hot path.

D9 ungrammatical slides
- Grey out and lock, with a message. A "fix" button runs annotation and surfaces only
  what could not be decided automatically. Undo restores.
- Never auto-annotate silently on open; never lock without offering a way out.

D10 prototype code
- Reuse the visual design from `_workspace/_ui-proto/` only. Write the logic fresh.
- The prototype mutates HTML in the browser, which is the inverse of the save model.

D11 hosting
- The existing server serves the editor UI too. `npm run serve`, one URL.

D12 entry screen
- Open the editor and a deck list appears first (W29/W30/W31 under `_workspace/`).
- Later this is also where a "new report" button goes.

## DECIDED WITHOUT ASKING (small; user may override)

- No confirm dialog on delete. Autosave plus Ctrl+Z covers it, and a dialog on every
  delete would be noise.
- No multi-select. Out of scope for this milestone.
