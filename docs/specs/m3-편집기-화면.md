# M3 편집기 화면

- 작성 시작: 2026-08-02
- 상태: 합의 완료

## 한 줄 요약

브라우저에서 주간 리포트 슬라이드를 클릭해서 고치는 화면 만들기.

## 지도

```
편집 화면은 4조각입니다.

  1. 슬라이드 목록   왼쪽에 13장이 쭉 — 어느 장을 볼지 고름
  2. 슬라이드 화면   가운데에 실제 슬라이드 한 장
  3. 고르기·손대기   클릭하면 테두리가 뜨고 버튼이 나옴
  4. 저장            고친 걸 서버로 보내 파일에 씀
```

화면에 보이는 슬라이드를 직접 뜯어고치는 게 아니다. 화면은 보여주기만 하고 실제 수정은 서버가 파일에 한다. 그래야 "고친 곳 밖은 한 글자도 안 바뀐다"는 약속이 지켜진다.

## 합의된 결정

### 1. 이번에 되게 할 범위

- **정한 것**: 글자 고치기 · 순서 바꾸기 · 추가·삭제 · 저장 · 되돌리기까지. 슬라이드 한 장을 통째로 늘리고 줄이는 것은 이번엔 하지 않는다.
- **왜**: 이 다섯이 주간 리포트 손질의 대부분이다. 여기까지 되면 처음으로 실제로 쓸 수 있는 상태가 된다.
- **정한 사람**: 사용자

### 2. 요소를 고르는 방식 — 파워포인트와 같게

- **정한 것**: 한 번 클릭하면 선택(테두리 + 버튼바), 한 번 더 클릭하면 커서가 들어가 글자 편집, Esc로 다시 선택 상태, 바깥 클릭으로 해제. **수정 버튼은 두지 않는다.**
- **왜**: 파워포인트에는 "슬라이드 전체가 편집 상태"라는 게 없고 항상 상자를 먼저 고른다. 그래서 고르기와 타이핑이 안 섞인다. 익숙한 방식이 낫다.
- **정한 사람**: 사용자
- **이력**: 처음에는 "수정 버튼을 누르면 그 슬라이드 전체가 편집 상태"로 정했다. 그런데 그러면 클릭이 전부 커서 자리에 쓰여서 **카드를 골라 옮기거나 지울 방법이 없어졌다.** 파워포인트가 실제로 어떻게 하는지 확인한 뒤 위 방식으로 바꿨다.

### 3. 순서 바꾸는 방법

- **정한 것**: 드래그와 위·아래 버튼 **둘 다**. 드래그가 기본이고, 목록 항목처럼 작아서 잡기 어려운 것은 버튼으로 옮긴다.
- **왜**: 둘 다 결국 같은 명령을 부르므로 만드는 비용이 크게 늘지 않는다.
- **정한 사람**: 사용자

**파워포인트와 다른 점 (질문에서 나온 설명)**
파워포인트는 상자를 x·y 좌표에 놓지만, 우리 슬라이드는 머리·본문·꼬리로 나뉘고 그 안에서 요소가 위에서 아래로 쌓인다. 그래서 드래그가 "아무 데나 놓기"가 아니라 **"몇 번째 자리에 끼우기"**다. 끌면 어디에 들어갈지 선이 표시된다.

흐름 방식을 고른 이유 셋 — 중간 것을 지우면 알아서 메워진다 · 여백과 정렬이 슬라이드마다 같다 · 글이 길어져도 겹치지 않는다. 파워포인트처럼 아무 데나 놓는 것은 6번 단계(자유 배치)로 따로 있고 이번엔 하지 않는다.

### 4. 저장 시점

- **정한 것**: 자동 저장. 고치고 빠져나오면 바로 파일에 쓴다.
- **왜**: 저장 버튼을 안 눌러 날릴 일이 없고, 되돌리기가 100번까지 되므로 실수해도 복구된다.
- **정한 사람**: 사용자

### 5. 되돌리기

- **정한 것**: Ctrl+Z와 화면 버튼 둘 다. 되돌리기·다시하기 버튼을 윗줄에 둔다.
- **왜**: 버튼이 있으면 되돌릴 게 남았는지 눈으로 보인다.
- **정한 사람**: 사용자

### 6. 왼쪽 슬라이드 목록

- **정한 것**: 누르면 그 장으로 이동 + **끌어서 슬라이드 순서 바꾸기**까지.
- **왜**: 순서 조정은 리포트를 마무리할 때 자주 필요하다.
- **정한 사람**: 사용자
- **주의**: 슬라이드 순서를 바꾸는 명령(`moveSection`)이 **서버에 아직 없다.** M3에서 하나 만들어야 한다. 페이지 번호 다시 매기기도 따라온다.

### 7. 새 요소를 추가하는 방법

- **정한 것**: 선택한 요소 아래의 **+** 를 누르면 작은 목록이 뜨고, 거기서 무엇을 넣을지 고른다.
- **왜**: 같은 종류만 자동으로 붙이면 다른 종류를 넣을 방법이 없다. 클릭이 한 번 더 들지만 무엇을 넣을지 눈으로 보인다.
- **정한 사람**: 사용자

### 8. 수식과 진행바 고치기

- **정한 것**:
  - **수식** — 두 번 클릭하면 그 자리가 입력칸으로 바뀌고, 고치는 동안 바로 아래에 그려진 모양이 실시간으로 보인다.
  - **진행바** — 막대 끝을 잡고 끌어서 조절하고, 정확한 값은 옆의 숫자를 고쳐서 넣는다.
- **왜**: 이 둘은 화면에 보이는 것이 기계가 그린 결과라 직접 못 고친다. 진짜 고칠 것은 수식 문자열 하나와 0~100 숫자 하나뿐이다. 대충 맞추는 것과 정확히 넣는 것이 둘 다 가능해야 한다.
- **정한 사람**: 사용자
- **주의**: W31 리포트에 수식이 53군데 들어갔다. 자주 쓰는 것이므로 다른 요소보다 **더 쉽게** 고쳐져야 한다. 이건 문법 명세에도 조항으로 박혀 있다.

### 9. 고칠 수 없는 슬라이드 처리

- **정한 것**: 그 장을 회색으로 잠그고 "아직 편집할 수 없습니다"라고 알린다. 고치기 버튼을 누르면 이름표를 붙여보고, 자동으로 판단이 안 되는 곳만 따로 보여준다. 되돌리기로 원래대로 돌아갈 수 있다.
- **왜**: 자동으로 붙이고 바로 편집하게 하면 사용자 모르게 파일이 바뀐다. 잠그기만 하고 방법을 안 주면 나갈 문이 없다.
- **정한 사람**: 사용자

### 10. 기존 프로토타입 코드

- **정한 것**: 화면 배치·색·버튼 모양은 그대로 참고하고, 속은 새로 만든다.
- **왜**: 프로토타입은 브라우저에서 HTML을 직접 뜯어고치는 방식이라 우리 저장 방식과 정반대다. 고쳐 쓰는 것이 새로 쓰는 것보다 오래 걸린다.
- **정한 사람**: 사용자

### 11. 화면을 띄우는 방법

- **정한 것**: 지금 서버가 편집 화면도 같이 내준다. `npm run serve` 한 번이면 브라우저에서 주소 하나로 열린다.
- **왜**: 띄울 것이 하나라 간단하고, 슬라이드 그림·글꼴 같은 파일도 같은 곳에서 나온다.
- **정한 사람**: 사용자

### 12. 편집기를 열면 처음 보이는 화면

- **정한 것**: 리포트 목록이 먼저 나온다. W29·W30·W31처럼 `_workspace/` 안의 리포트가 나열되고 거기서 고른다.
- **왜**: 주소를 외울 필요가 없다. 나중에 "새 리포트 만들기" 버튼을 붙일 자리도 여기다.
- **정한 사람**: 사용자

## 아직 안 정한 것

- 없음 (구현 중에 생기면 여기 추가)

## 물어보지 않고 정한 것

작은 것이라 질문으로 만들지 않았다. 마음에 안 들면 말씀해 주세요.

- **삭제할 때 "정말 지울까요?"를 묻지 않는다** — 자동 저장이라 확인창이 자주 뜨면 성가시고, Ctrl+Z로 바로 되돌아온다
- **여러 요소를 한 번에 고르는 기능은 넣지 않는다** — 이번 범위에 없다

## 이번엔 안 하는 것

- 슬라이드 한 장을 통째로 추가·삭제
- 요소를 아무 자리에나 끌어다 놓기 (자유 배치 — 6번 단계)
- 글자 넘침·빈 문구 같은 문제를 알려주는 기능 (4번 단계)

## 이번에 나온 말

- **요소**: 슬라이드를 이루는 조각 하나. 제목·문단·카드·목록 같은 것
- **이름표**: 시스템이 요소를 구별하려고 HTML에 붙여둔 표시. "이건 카드", "이름은 n3"
- **명령**: 서버에 보내는 수정 요청 한 건. "n3을 위로 올려" 같은 것
- **흐름 배치**: 요소가 위에서 아래로 차례로 쌓이는 방식. 좌표를 지정하지 않는다
- **자유 배치**: 파워포인트처럼 좌표를 지정해 아무 데나 놓는 방식. 6번 단계
- **불투명 요소**: 겉모습을 기계가 그리는 요소. 수식과 진행바 둘뿐이다. 진짜 고칠 것은 값 하나뿐이다

## 구현 전에 서버에 더 만들어야 할 것

결정 6번(슬라이드 순서 바꾸기) 때문에 생겼다.

- `moveSection` — 슬라이드 순서를 바꾸는 명령. 지금 서버에 없다
- `renumberPages` — 순서가 바뀌면 페이지 번호를 다시 매기는 일이 따라온다
