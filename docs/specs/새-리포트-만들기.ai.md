# SPEC (AI context): new report creation

status: agreed | source: `새-리포트-만들기.md` (human original)
goal: create a report from a master (theme + header/footer + background + logo); fill it by handing a manuscript to the AI, not by growing an empty deck.
user profile: non-developer. Root problem = "outsourcing of code".

## CONTEXT

- A slide is four parts, measured against the annotated W31: region[head], a title group (kicker+title), region[body], region[foot]. The user predicted this decomposition unprompted; it matches.
- Vocabulary already covers title/body placeholders, meta variants (lab, page, brand), 3 layouts (default, split, title), 4 slide kinds (title, content, break, closing).
- Missing versus a PowerPoint master: background, logo image.
- `templates/weekly-report/index.html` is the old unannotated shell — a new annotated shell must be authored.
- Measured: `final.md` is 38 numbered sentences with no headings and no slide boundaries; it became 13 slides by editorial judgement.

## DECISIONS

D1 header-footer-once
- Setup edits lab name, department, week, date, report name once; all slides follow.
- Do not restructure the document. Collect matching `el:meta` nodes by variant, send one envelope with several `setContent` commands — one commit, one undo step.

D2 design-scope
- Setup controls main colour, sub colour, font, body text size. Nothing else.

D3 master-contents
- Setup owns exactly four things: colours/font/size, background, header-footer text, logo image.
- Background and logo are not in the vocabulary yet; adding them to `core/grammar.md` and `themes/snu/mapping.json` is the largest piece of work here.

D4 background-per-slide
- Setup picks the default (light/dark); a selected slide can override. Preserves the existing dark title/break habit.

D5 logo-optional-and-flowed
- No reserved placeholder. Adding a logo inserts it at the left of the head and pushes the lab name right; with no logo there is no element at all.
- Flow layout does the pushing — no coordinates.
- (Revised: first draft said only "small, at the left".)

D6 manuscript-in-deck-out
- Not an empty deck grown slide by slide. Hand over the manuscript plus the setup, get a deck; the editor is for touching up afterwards.
- The user builds design system, layout and content *first*, then makes the document — a blank-page flow contradicts that order.
- (Revised: first draft said "cover + one empty content slide, grow with an add-slide button".)
- Folder id stays date-derived (`2026-08-02-001`).

D7 design-md-is-the-source
- A new theme starts as `themes/<name>/DESIGN.md` in prose; `tokens.css` is derived from it. `mapping.json` stays hand-written — it is a machine contract about which class is which element.
- Follows the open-design procedure (github.com/nexu-io/open-design). Comparing structures, ours already had every slot but the human-readable contract.
- `tokens/*.css` is currently repo-wide and must be split per theme.

D8 ai-draws-slide-boundaries
- The AI reads the manuscript, groups it by topic, and issues server commands. No slide markers in the manuscript.
- Therefore **no deterministic assembler is built**: the server creates an empty document and applies the master; filling goes through the existing command surface (`reserveSections`, `insertElement`, `setContent`). Plan §P3 ("one command set, two callers") holds unchanged.
