# 새 리포트 만들기

- 작성 시작: 2026-08-02
- 상태: 구현 완료 (2026-08-03)

## 한 줄 요약

리포트 목록에서 새 리포트를 만들 수 있게 한다. **내용 슬라이드를 고르는 것이 아니라, 틀(마스터)을 먼저 잡고 시작한다.**

## 지도

```
리포트 목록
  [ + 새 리포트 ]  ← 만들 것

누르면 설정 화면이 뜬다 (= 프레젠테이션 마스터)
  1. 색 · 글꼴 · 글자 크기      문서 전체를 지배한다
  2. 배경                      밝은 바탕 / 어두운 바탕
  3. 머리글 · 꼬리글 내용        랩실명 · 소속 · 주차 · 날짜 · 리포트 이름
  4. 로고 그림                  머리나 표지에 놓는다

정하고 나면 그 틀로 리포트 파일이 만들어지고, 편집기가 열린다.
```

## 슬라이드 한 장의 구조 (실측)

사용자 추측("머릿글·제목부·메인부·꼬릿글")이 지금 덱과 정확히 일치한다.

```
<section>
  ├ 머리 (region head)   랩실명 · 주차·날짜
  ├ 제목부 (box group)   소제목(kicker) + 제목
  ├ 본문 (region body)   내용
  └ 꼬리 (region foot)   리포트 이름 · 쪽번호
```

## 파워포인트 마스터와의 대조 (조사 결과)

| 파워포인트 마스터 | 우리에게 | 상태 |
|---|---|---|
| 테마 색·글꼴 | `tokens/*.css` | 있음 |
| 제목 자리표시자 | `el:title` · `el:kicker` · `el:hero` | 있음 |
| 본문 자리표시자 | `box:region[body]` | 있음 |
| 날짜·바닥글·번호 | `el:meta` (lab · page · brand) | 있음 |
| 레이아웃 종류 | 기본 · 분할(좌우) · 표지 3종 | 있음 (파워포인트는 9종) |
| 장 종류 | 표지 · 내용 · 구역표지 · 마무리 | 있음 |
| 배경 | — | **없음.** 지금은 표지에만 `dark` 클래스로 임시 처리 |
| 로고 그림 | `el:meta[brand]` 는 글자용 | **없음** |

## 합의된 결정

### 1. 머리글·꼬리글은 한 자리에서 고치고 전체에 적용한다

- **정한 것**: 설정 화면에서 랩실명·소속·주차·날짜·리포트 이름을 한 번 적으면 모든 장의 머리·꼬리가 함께 바뀐다.
- **왜**: 주차마다 바뀌는 것이 날짜·주차 둘뿐인데, 지금 구조로는 13장을 13번 고쳐야 한다.
- **정한 사람**: 사용자
- **구현 메모**: 문서 구조는 그대로 두고, 설정 화면이 같은 뜻의 요소들(`el:meta` 의 variant 별)을 모아 **한 봉투에 `setContent` 여러 건**으로 보낸다. 커밋이 하나이므로 되돌리기도 한 번이다.

### 2. 디자인은 색 + 글꼴 + 글자 크기까지 고른다

- **정한 것**: 메인·서브 색, 글꼴, 본문 글자 크기를 설정에서 정한다.
- **왜**: 발표 환경에 맞춰 글자를 키울 수 있어야 한다.
- **정한 사람**: 사용자

### 3. 마스터에 배경과 로고 그림을 넣는다

- **정한 것**: 설정 화면이 정하는 것은 넷이다 — ① 색·글꼴·글자 크기 ② 배경 ③ 머리·꼬리 내용 ④ 로고 그림.
- **왜**: 파워포인트 마스터와 대조했을 때 우리에게 없던 둘이 배경과 로고였고, 둘 다 리포트 전체의 인상을 정한다.
- **정한 사람**: 사용자
- **주의**: 배경과 로고는 **어휘에 없다.** 문법에 개념을 추가해야 하고, 그것은 이 작업의 가장 큰 덩어리다.

### 4. 배경은 장마다 고른다

- **정한 것**: 설정에서 기본 배경(밝음/어두움)을 정하고, 장을 고른 상태에서 그 장만 바꿀 수 있다.
- **왜**: 표지·구역 표지를 어둡게 하는 지금 관행이 그대로 살아야 한다.
- **정한 사람**: 사용자

### 5. 로고는 선택 사항이고, 넣으면 옆으로 밀어낸다

- **정한 것**: 자리를 미리 비워 두지 않는다. 로고를 넣으면 머리 **왼쪽에 끼어들고 기존 내용(랩실명)이 오른쪽으로 밀린다.** 안 넣으면 요소 자체가 없다.
- **왜**: 빈 자리표를 두면 로고 없는 리포트가 빈 네모를 달고 다닌다. 흐름 배치이므로 끼어들면 나머지가 알아서 밀린다 — 좌표를 잡을 필요가 없다.
- **정한 사람**: 사용자
- **이력**: 처음에는 "머리 왼쪽에 작게" 로만 적었다. 사용자가 **밀려서 들어가는 방식**임을 분명히 했다.

### 6. 원고를 넘기면 덱이 조립된다

- **정한 것**: 빈 문서에서 장을 하나씩 늘려 가는 방식이 아니다. **원고(`final.md`)와 설정(디자인·레이아웃)을 주면 덱이 조립되어 나오고**, 편집기는 그 뒤 손보기용이다.
- **왜**: 사용자는 디자인 시스템·레이아웃·내용을 **먼저 다 만들어 두고** 문서를 만든다. 빈 종이에서 시작하는 흐름이 그 순서와 맞지 않는다.
- **정한 사람**: 사용자
- **이력**: 처음에는 "표지 + 빈 내용 1장으로 시작하고 장 추가 버튼으로 늘린다" 로 정했다가, 사용자가 실제 작업 순서를 밝히며 뒤집었다.
- **함께 정한 것(위임)**: 폴더 이름은 `2026-08-02-001` 처럼 날짜로 자동 짓는다(지금 관행과 같다).
- **실측**: `_workspace/2026-07-27-001/final.md` 는 번호 붙은 38 문장이고 제목도 장 구분도 없다. 그것이 13 장이 되었다 — **어느 문장이 몇 장째로 가는지는 원고에 적혀 있지 않다.** 조립기의 핵심 질문이 이것이다.

### 7. 새 디자인 시스템은 `DESIGN.md` 에서 파생시킨다

- **정한 것**: 새 테마를 만들 때 `themes/<이름>/DESIGN.md` 를 **사람 말로 먼저 쓰고**, 거기서 `tokens.css` 를 파생시킨다. 어휘 매핑(`mapping.json` — 어떤 클래스가 카드인가)은 기계 계약이라 손으로 정한다.
- **왜**: [open-design](https://github.com/nexu-io/open-design) 의 절차를 따르자는 사용자 요청. 대조해 보니 우리 구조는 그쪽과 거의 같은 자리를 이미 갖고 있고, **사람이 읽는 계약서 한 칸만 비어 있었다.**
- **정한 사람**: 사용자
- **주의**: 지금 `tokens/*.css` 는 저장소 공용이라 테마별로 갈라야 한다.

### 8. 장 경계는 AI 가 긋는다

- **정한 것**: 원고를 AI 가 읽고 주제별로 묶어 **서버 명령으로** 장과 요소를 만든다. 원고에 장 표시를 달지 않는다.
- **왜**: 지금 13 장을 만든 방식이 그것이고, 원고를 그대로 넘길 수 있다. 결과가 이상하면 편집기에서 고치거나 되돌리면 된다.
- **정한 사람**: 사용자
- **따라오는 결과**: **결정론적 조립기를 만들 필요가 없다.** 서버는 빈 문서를 만들고 마스터를 입히는 데까지만 하고, 채우는 일은 이미 있는 명령 표면(`reserveSections`·`insertElement`·`setContent`)이 받는다. 계획 §P3("명령 하나, 호출자 둘")이 그대로 성립한다.

### 9. 배경에 "전체 적용" 버튼을 둔다 · 발표 버튼을 되살린다

- **정한 것**: 배경을 장마다 고르되(결정 4), 그 옆에 **전체 적용** 버튼을 둔다. 그리고 편집기 윗줄에 **발표** 버튼을 붙인다.
- **왜**: 참고한 [Slate Point](https://slate-deck-28an.arcada.app) 이 같은 구분(테마=전체 / 배경=이 장)을 쓰면서 탈출구로 "Apply to All" 을 두었다. 장마다 고르게 하면 "전부 어둡게" 가 번거로워지는데 그 한 버튼이 그것을 푼다. 발표 기능은 `deck-stage` 에 **이미 있고** 편집기가 감춰 뒀을 뿐이라 만들 것이 거의 없다.
- **정한 사람**: 사용자

## 이번엔 안 하는 것

- 레이아웃 종류 늘리기 (지금 3종 유지)
- 장 삭제 (서버 명령이 아직 없다)
- 표지에 큰 로고 (필요해지면 그때)

## 만들어야 하는 것 (합의에서 따라 나온 목록)

| | 무엇 | 어디 |
|---|---|---|
| 1 | 배경·로고를 어휘에 추가 | ✅ `data-bg` 닫힌 열거 · `image` 의 `src`·`alt` (§2.3.1 · §3.5 L5.1) |
| 2 | 이름표 붙은 덱 껍데기 | ✅ `themes/snu/deck.html` |
| 3 | 리포트 만들기 (폴더 + 파일 생성) | ✅ `POST /decks` — `atomicWrite` 하나, 덮어쓰기는 409 |
| 4 | 로고 파일 받기 | ✅ `POST /deck/:id/asset` — 래스터만, 매직 넘버 검사 |
| 5 | 리포트 설정 화면 | ✅ `＋ 새 리포트` → 설정 화면 |
| 6 | 색·글꼴·크기를 리포트마다 | ✅ `setDeckTokens` 명령 (되돌리기에 들어간다) |
| 7 | `DESIGN.md` → `tokens.css` 파생 | ✅ `tools/design/index.js` · `npm run design snu` |
| 8 | 배경 고르기·전체 적용 · 발표 버튼 | ✅ `setSectionProps` 한 봉투 · `deck-stage` 발표 모드 |

**여덟 개 다 끝났다.** 남은 것은 나중으로 미룬 레일 조작 버튼(복제·삭제는 서버 명령이 없다) 하나다.

**나중에** — 레일 항목에 마우스를 올리면 위·아래·복제·삭제가 뜨는 방식(같은 참고 앱). 드래그를 모르는 사람에게는 순서 바꾸는 길이 안 보인다. 복제·삭제는 서버 명령(`duplicateSection`·`removeSection`)이 없어 이번 범위 밖이다.

조립기는 **만들지 않는다** (결정 8). 원고를 장으로 나누는 일은 AI 가 이미 있는 명령으로 한다.

## 이번에 나온 말

- **마스터**: 모든 장이 공유하는 틀. 파워포인트의 "슬라이드 마스터"와 같은 뜻
- **토큰**: 색·여백·글자 크기 같은 값에 붙인 이름. 이름을 바꾸면 그것을 쓰는 곳이 전부 따라 바뀐다
- **어휘**: 이 시스템이 아는 요소 종류의 목록. 여기 없는 것은 편집기가 다루지 못한다
