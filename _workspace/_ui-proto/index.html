편집 모드 UI — 4안 실물 비교

진짜 W31 슬라이드 + 진짜 디자인 시스템(styles.css, slides.css) 위에 편집 크롬만 4가지로 바꿔 얹었다. 선택·이동·복제·삭제·블록 삽입·텍스트 편집은 전부 실제로 동작한다. 저장만 가짜(토스트)다. 좌측 레일은 실제 deck-stage 레일 자리를 재현한 것.

PARADIGM E — 새로 추가

PowerPoint형

리본 툴바(홈/삽입/서식) · 개체 단위 선택 · 8핸들 · 드래그 이동 · 우클릭 메뉴 · 서식 창 · 상태바. PPT의 “그룹”을 DOM 중첩에 대응시켰다 — 카드 안 글자를 클릭해도 카드가 통으로 잡히고, 더블클릭하면 그룹 안으로 들어가 내부 개체를 다룬다. slide-body 같은 레이아웃 껍데기는 아예 안 잡힌다. 스냅 배치 / 자유 배치 두 모드를 리본에서 바로 바꿔 비교할 수 있다.

PPT 조작감 레이아웃 껍데기 안 보임 배치 모드 비교 내장 자유 배치는 정렬 책임이 사용자
PARADIGM A

플로팅 툴바형

고정 패널 없음. 요소를 클릭하면 그 위에 작은 툴바가 뜨고, 요소 위/아래 경계에 ＋ 삽입 버튼이 붙는다. Notion·Medium 방식.

캔버스 최대 학습곡선 0 구현 가벼움 세부 속성은 ⋯ 안에 숨음
PARADIGM B

인스펙터 패널형

우측 300px 고정 패널. breadcrumb으로 부모 계층 타고 올라가 선택, 클래스 토글·그리드 전환·블록 팔레트가 항상 보인다. Figma·DevTools 방식.

기능 밀도 최고 계층 파악 쉬움 캔버스 축소 구현량 큼
PARADIGM C

모드 전환형

상단에 텍스트 / 구조 / 발표 3모드. 텍스트 모드는 한 번 클릭으로 바로 타이핑돼서 실수로 구조가 깨질 일이 없다. 구조 모드에서만 블록 라벨·아웃라인이 드러난다. Keynote 방식.

실수 방지 최강 인지부하 낮음 모드 왕복 귀찮음
PARADIGM D

아웃라인 트리형

우측에 슬라이드 DOM 트리. 트리 행에 hover하면 캔버스에서 해당 요소가 하이라이트되고, ⣿ 핸들을 드래그해 형제끼리 재배치한다.

깊은 중첩 접근 강함 시선 왕복 큼 비용 대비 실사용 적음

어느 안에서든 되는 조작

  • 클릭 — 요소 선택 (파란 실선 + 좌상단에 div.card 같은 라벨)
  • 더블클릭 — 그 자리에서 텍스트 편집 · Enter도 동일
  • ⌥↑ / ⌥↓ — 형제 사이 순서 이동
  • ⌘D — 복제 (덱 전용 일회용 블록도 이 방식으로 안전하게 늘림)
  • Delete — 삭제 · Esc — 선택 해제
  • ⌘Z — 되돌리기 · ⌘S — 저장 (프로토타입이라 토스트만)
  • 좌측 레일에서 03 논문 개요 / 06 PTM vs WRF 두 장 전환 가능

이 폴더는 UI 결정용 임시 프로토타입이다. 실제 _workspace/2026-07-27-001/index.html은 건드리지 않는다.
